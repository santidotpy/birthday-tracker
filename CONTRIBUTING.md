# Contributing

Thanks for taking a look. This is a small, opinionated project — please read this
page before opening a pull request, because two of the rules below are unusual
and will get an otherwise good PR sent back.

## 1. The code is written in Spanish

Filenames, identifiers, types, comments, tests and UI strings are all in
Spanish: `Integrante`, `Retrato`, `cumpleaneros`, `proximaOcurrenciaEstricta`.
This is not an accident and it is not up for debate — mixing English into it
makes the rest of the codebase harder to read, which is the opposite of what a
contribution should do.

The only exceptions are third-party APIs (`createServerFn`, `useEffect`) and the
files under `src/components/ui/`, which are generated by shadcn.

If you do not read Spanish, you can still contribute usefully: bug reports,
deployment fixes, dependency updates and documentation in `README.md` are all
welcome and none of them require writing Spanish identifiers.

## 2. Read the domain glossary before naming anything

`CONTEXT.md` is the canonical vocabulary. Read it before you introduce a new
name. It also fixes two distinctions the code depends on:

- **Próximo cumpleaños** is *strictly after* the date being viewed, and never
  includes it.
- **Agenda** *does* include that date and starts there — not in January.

Getting these backwards produces code that passes review and is wrong on
somebody's birthday, which is the worst possible day for it to show up.

## 3. Decisions that are hard to reverse live in `docs/adr/`

Before proposing an architectural change, check whether it is already answered
there. Seven decisions are recorded with their reasoning — among them: dates are
always evaluated in a single timezone, date arithmetic is hand-rolled rather
than delegated to a date library, portraits are copied rather than hot-linked,
and the server is built from server functions rather than HTTP route handlers.

If you disagree with one, that is fine — open an issue arguing against the ADR
rather than a PR that quietly works around it.

## Getting set up

Requires Node 22+ and pnpm.

```sh
pnpm install
cp .env.example .env          # then fill in BETTER_AUTH_SECRET and the ADMIN_* vars
pnpm db:migrate
pnpm seed:admin               # creates the single administrator account
pnpm dev                      # http://localhost:3000
```

## Before you open a pull request

```sh
pnpm typecheck
pnpm test
```

Both must pass. CI runs exactly these two commands, so there are no surprises.

Tests run in Node with no browser — component tests use `renderToStaticMarkup`.

Two scenarios are **not** covered by the test suite and need a manual check if
you touch startup or migrations:

- `DATABASE_PATH` pointing at a fresh empty directory must start up empty, not crash.
- `MIGRATIONS_PATH` pointing at a directory that does not exist must show the
  error screen.

## Scope

This app answers one question — who has a birthday — on an ambient screen. Pull
requests that turn it into a calendar, an HR tool, or a notification system are
out of scope. `PRODUCT.md` records what it is and is not.

## En castellano

Todo lo de arriba, corto:

- **El código va en castellano.** Nombres de archivo, identificadores, tipos,
  comentarios, tests y textos de la interfaz. Las excepciones son las APIs de
  terceros y `src/components/ui/`, que lo genera shadcn.
- **Leé `CONTEXT.md` antes de nombrar algo nuevo.** Fija la diferencia entre
  Próximo cumpleaños (estrictamente posterior) y Agenda (incluye el día).
- **Las decisiones difíciles de revertir están en `docs/adr/`.** Si no estás de
  acuerdo con una, abrí un issue discutiéndola en vez de un PR que la esquiva.
- Antes del PR: `pnpm typecheck` y `pnpm test`, los dos en verde.
